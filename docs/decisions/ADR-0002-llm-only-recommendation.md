# ADR-0002: 问答全接大模型，不设本地规则兜底

- 状态：已接受（用户 D1，不可变）
- 日期：2026-11-22
- 决策者：用户（张鑫宇）

## 背景
> 提示词包原方案是本地 rules.json 排序 + 大模型做解释层，但用户明确要"怎么问都能答、替我拍板"。两次决策卡片均确认全接大模型，且到顶只停调用不切规则（DECISIONS D1/C1）。

## 决策
> 我们将让每一次问答判断都来自大模型；不实现任何本地打分规则，预算到顶时停调用给静态提示或返回缓存结果。

## 后果
- 变容易的：自然语言体验、能解释、能应付长尾问法；没有规则维护负担。
- 变困难的：成本与延迟随调用量走，必须靠六条护栏（F7-a~f）焊死；50 条不编造抽检成为常态验收。
- 引出的新决策：缓存 key 防串味、白名单校验见 SPEC §6.5/§6.7；是否上真流式见 ADR-0006。

## 备选方案
| 方案 | 为什么没选 |
|---|---|
| 本地 rules.json 排序 + 模型解释 | 被用户 D1 明确否决；切回规则即等于推翻决策 |
| 规则+模型混合兜底 | 同样被 D1 否决；"停调用给静态提示"是限流，不算混合兜底，边界见 C1 |
