# ADR-0001: 原生小程序 + 微信云开发，不用跨端框架

- 状态：已接受
- 日期：2026-11-22
- 决策者：高见远（架构师）

## 背景
> 项目只发微信一端、用户是不具备后端运维能力的在校生、成本需硬顶 ¥300/月。跨端框架（Taro/uni-app）带来的多端能力当前用不上，却增加编译链与包体。见 brief §1、DECISIONS §四。

## 决策
> 我们将采用微信小程序原生（WXML/WXSS/JS）+ 微信云开发（云函数 Node.js + 云数据库 + 静态 JSON）作为唯一技术栈。

## 后果
- 变容易的：免运维、免域名备案、Key 只在云函数天然满足 F7-e；单人可维护。
- 变困难的：锁定微信生态，将来发支付宝/抖音/H5 需重写；云函数冷启动对首字有轻微影响。
- 引出的新决策：模型选型见 ADR-0003；数据落地见 ADR-0004。

## 备选方案
| 方案 | 为什么没选 |
|---|---|
| Taro 3 + 云开发 | 跨端能力当前无用，多一层编译链和 runtime，白付成本（mvp-stack.md 矩阵） |
| Next.js + FastAPI + PostgreSQL + 自建服务器 | 要自购服务器/域名/备案与运维，与单人维护和 ¥300 封顶直接冲突 |
