# ADR-0006: MVP 非流式 + 打字机，真流式列 Phase 2

- 状态：已接受
- 日期：2026-11-22
- 决策者：高见远（架构师）

## 背景
> AC-02 写"流式首字 <3s"，但微信云函数做 SSE 需自建代理，与单人维护/成本约束冲突。brief §6 风险 5 也强调不承诺 3 秒出完整答案。

## 决策
> 我们将用非流式云函数拿完整 JSON，前端 answer-stream 组件做打字机逐字显示；"首字 <3s"以打字机首字验收，真流式列为 Phase 2 待决项。

## 后果
- 变容易的：云函数实现简单、成本可控、错误归一化清晰。
- 变困难的：无真"边生成边显示"；若云函数 P50 >3s，打字机首字也会晚，需靠缓存与超时预算解决（SPEC §9.3）。
- 引出的新决策：若用户明确要逐字蹦出，另立 ADR 评估 SSE 代理，加 1–2 人日。

## 备选方案
| 方案 | 为什么没选 |
|---|---|
| 真流式 SSE 代理 | 需常驻服务维持长连接，违背无运维与 ¥300 成本约束；MVP 阶段收益仅是观感 |
