# ADR-0005: 用 openid 限次，不建账号

- 状态：已接受
- 日期：2026-11-22
- 决策者：高见远（架构师）

## 背景
> 用户是大一学生，不愿多填资料；D2 开放全校后调用量不可控，必须有归属维度做限次。DECISIONS §四技术代劳已定。

## 决策
> 我们将用微信静默 openid（服务端会话取，不信前端传值）作为 usage_daily 的归属维度，不建账号表；"我的清单"存本地 storage。

## 后果
- 变容易的：零注册摩擦；限次有可靠归属，前端伪造 id 无效。
- 变困难的：跨设备/换微信无法同步清单；清缓存会丢清单。
- 引出的新决策：将来要跨设备同步必须补账号，属新 ADR 范围。

## 备选方案
| 方案 | 为什么没选 |
|---|---|
| 手机号+验证码登录 | 多一步注册摩擦，且要接短信服务增加成本面 |
| 设备指纹 | 可伪造、跨端不稳定，不如微信官方 openid 可靠 |
