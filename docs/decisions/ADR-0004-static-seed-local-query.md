# ADR-0004: 种子落静态 JSON，避雷查询读本地数据

- 状态：已接受
- 日期：2026-11-22
- 决策者：高见远（架构师）

## 背景
> DECISIONS §四技术代劳已定"清洗后的干净表落静态数据、查询走本地"；F2 要求避雷查询不调大模型；种子只有千级数据。

## 决策
> 我们将把清洗后的种子打包为 data/restaurants.json（精确 schema 见 SPEC §4.2），avoid-lookup 云函数冷启动读入内存做匹配，不建数据库镜像、不走向量库。

## 后果
- 变容易的：避雷查询 <200ms、零调用成本；离线可用；无数据库双写问题。
- 变困难的：数据更新需重新打包发版；千级以上需要检索时需重评（当前远未到）。
- 引出的新决策：缓存 key 必须含 data_version，避免数据更新后串味（SPEC §6.7）。

## 备选方案
| 方案 | 为什么没选 |
|---|---|
| 云数据库镜像 + ORM 查询 | 多一层 IO 和双写一致性负担，千级数据用不上 |
| 向量库 + embedding | 数据量与场景都不需要，且引入成本和运维 |
